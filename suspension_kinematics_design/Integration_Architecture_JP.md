# FSAE サスペンション設計・統合アーキテクチャ

本資料は、ラップタイムシミュレータによる「最適化された車両諸元」から出発し、最終的な「サスペンションの3Dハードポイント座標（CAD設計図）」を出力するまでの、**システム全体の統合データフローと設計パイプライン**を定義します。

特に、新たに作成する「Aアーム幾何学オプティマイザ（Phase 1/2層）」と、すでに改修が完了して稼働している「POU（プッシュロッド）最適化スクリプト（Phase 3層）」をどのようにシームレスに連携させるかに焦点を当てます。

---

## 1. 全体データフローと設計パイプライン

システムは以下の4段階の層（Layer）で構成され、上位層で決定されたパラメータが下位層の「絶対的な拘束条件」として上書き不可能な形で引き継がれていきます。

```mermaid
graph TD
    A[Layer 0: Laptime Simulator<br> run_full_vehicle_ga.m] -->|latest_best_vehicle_artifact.json<br>(Track, CG, Spring, Alignment)| B(Layer 1&2: A-Arm Optimizer<br>【新規開発】)
    B -->|base_hardpoints.json<br>(A-Arm 3D Coordinates locked)| C(Layer 3: POU Optimizer<br>【構築済/改修済】)
    C -->|pou_hardpoints.json<br>(Bellcrank & Pushrod Coordinates)| D[Layer 4: C++ 14DOF Model / CAD<br>Final Physical Model]
```

## 2. 各レイヤーの詳細設計とインターフェース

### レイヤー 0: フルビークル・ダイナミクス最適化（既存）
*   **役割:** ラップタイムを最小化するための、空気力学・パワートレイン・物理パッケージングの最適解を算出します。
*   **出力ファイル:** `optimized_autocross.json`
*   **次層へ後継する主要パラメータ:**
    *   `TrackF`, `TrackR` (トレッド幅)
    *   `Wheelbase` (ホイールベース)
    *   `CGHeight` (重心高)
    *   `StaticCamber`, `StaticToe` (静的アライメント)
    *   `SpringF`, `SpringR` (理想スプリングレート) --- ※これらはホイールレート（実効値）として解釈

### レイヤー 1 & 2: Aアーム幾何学オプティマイザ（【新規開発が必要】）
*   **役割:** レイヤー0で指定された目標値（トレッド、アライメント、重心高）を厳格に守りながら、コーナリング時の「タイヤ接地軌跡（キャンバーゲイン）」と「ロールセンター高／推移」が最適になるような**上下Aアームのピボット3D座標**を計算します。
*   **入力:** `optimized_autocross.json` および 設計者が与える「目標ロールセンター高」「目標キャンバーゲイン」
*   **内部処理（非線形最適化）:**
    *   変位（Heave / Roll / Steer）に応じたキャンバーおよびロールセンターの運動学解析（Kinematic Solver）
    *   目標軌道との誤差（RMS）を最小化するように、シャーシ側（`upper_arm_chassis`, `lower_arm_chassis`）およびアップライト側（`upper_arm_upright`, `lower_arm_upright`）の座標を決定。
*   **出力ファイル:** `suspension_base_geometry.json`
    *   このJSONには、タイロッドを含むAアーム構造の全ジョイントの完全な3D空間座標が記録されます。**ここでキャンバー軌跡は完全にロックされます。**

### レイヤー 3: POU（プッシュロッド Line-of-Action）軌道オプティマイザ
*   **役割:** レイヤー0の「目標スプリングレート」や「ステアリング・ジャッキアップ特性」を実現するための**プッシュロッドの理想的な作用線（ベクトル）**を決定します。
*   **現状の数学的制約:** 現在の `run_all_wheels.m` では、ステアリング時のジャッキアップ軌道を純粋な数学的勾配として解くため、ベルクランクを「フレーム上の固定点に繋がる仮想ダイレクトダンパー（マクファーソン構成に近い数学的抽象化）」として近似計算しています。これにより、計算爆発を防ぎ、ジャッキアップの理想作用線を一意に求めています。

### レイヤー 3b（【次期開発方針 / 提案】）: 完全なFSAEベルクランク機構のマッピング
*   **役割:** レイヤー3で算出された「プッシュロッドの理想ベクトル」をベースに、F1やFSAEで実際に採用される「フレーム締結型ベルクランク＋ショックアブソーバー」の物理機構へと設計を具現化（翻訳）します。
*   **処理フロー（想定）:**
    1.  レイヤー3で導出されたプッシュロッドの車体側仮想ジョイントを「ベルクランクのプッシュロッド受け点（Pushrod-Bellcrank Joint）」とみなす。
    2.  その周囲のフレーム上に「ベルクランク回転軸（Bellcrank Pivot）」を定義する。
    3.  指定されたモーションレシオ（例: 1.0）となるよう、ベルクランクのもう一端（Damper Joint）と、フレーム側の「ダンパーマウント（Damper Pivot）」を自動生成する。
*   **これにより、3Dプロットにも本物の「プッシュロッド・ベルクランク・ダンパー」のリンク機構が描画され、市販車構造との誤解を完全に解消します。**

### レイヤー 4: C++動力学・CADモデルへの統合
*   最終的に `base_hardpoints.json` と物理的なベルクランク構造群を結合したものが、その車両におけるサスペンションの「完全なBlueprint（設計図）」となります。
*   これをそのままSolidWorks等のCADでモデリングするか、C++の14DOFシミュレータにロードしてフルビークルのラップタイム再検証（Closed-loop検証）を行います。

## 3. 次のアクションプラン（開発タスク）

既存の「POUシステム（Layer 3）」は驚異的な高精度（RMS誤差0.08mmなど）で動作する状態にすでに仕上がっています。したがって、システムを貫通させるための直近の開発タスクは以下のようになります。

1.  **A-Arm Kinematic Solverの作成:**
    Heave（上下動）およびRoll（傾き）に対するロールセンターとキャンバー角を算出する幾何学ソルバーの開発。
2.  **`main_a_arm_optimizer.m` の実装:**
    JSONから諸元を読み込み、Aアームのピボット座標を探索・最適化して `suspension_base_geometry.json` を書き出すツールの作成。
3.  **既存POUソルバーのインターフェース改修:**
    現在ハードコーディングされている部分（`define_suspension_geometry.m`）を、生成された `suspension_base_geometry.json` を動的に読み込むように結合部のI/Oを繋ぎ込みます。
