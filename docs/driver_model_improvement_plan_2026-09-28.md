# ドライバモデル改善計画

- **作成日:** 2026-09-28
- **目的:** 既存の操舵・速度制御の意図を保ち、物理の信頼性、追跡可能な評価、設計探索時の計算コストを改善する。

## 要求と前提

改善対象は「ラップタイムを小さくするアルゴリズム」単体ではない。タイヤ・車両・トラックの条件を変えても破綻しにくいドライバを使い、車両設計やタイヤ条件の比較を実用的な時間で回せることが目的である。したがって、ドライバの変更は以下を満たす必要がある。

- 物理プラントと評価条件が固定され、結果を再現できる。
- ラップタイムだけでなくコース逸脱、完走、操作量、操舵・タイヤ制約を評価する。
- フル14DOF/PINNモデルを最終評価の基準として残す。
- 現在の記録が測定由来の確定目標と確認できるまでは、66.0秒を合否基準にしない。
- オフラインのシミュレーション短縮と、実車CPUの制御締切りは別要件として扱う。

## 現在の実装とボトルネック

### コントローラ構成

C++シミュレータにはPID、LPV-LQR、MPC、MPC v2、Attack、RLの入口がある。構造上、PIDは1msごと、RLは20ms、予測系は25ms周期の設定がある。MPCは操舵7候補×加減速5候補を各rolloutで評価する有限グリッド方式で、OSQP系問題定義とは本番経路が分かれている。MPC v2はアルゴリズムよりも既存設定のバリアントとして見える。

Attackは通常7操舵プリミティブ×4速度倍率の候補を評価する。各rolloutの内側で進捗最近傍探索や先読み速度プロファイル走査を繰り返す。閉路の最近傍探索はトラック継ぎ目を循環できない疑いがあるため、性能変更前に補正を要する。

LPV-LQRは低コストの既存ベースライン候補である。実験記録のフローズン速度プロファイル汎化試験では、6状態モデルの外側計算平均0.0107ms、最大0.028msという値が3試験に記録されている。これは当時の条件であり、現在のbranch／ビルド／CPUでの保証ではない。Attackの古い10秒加速記録では平均約4.45ms、最大約8.28ms、古いフルAutocross記録では平均約52.05ms、最大約706.65msという数値が残る。どちらも現在の実行時間とみなさず、再計測の基準候補とする。

また、LPV用の線形化タイヤ剛性はTMeasyパラメータ由来だが、真値プラント側がPINNを使う構成がある。過去に特定条件下でゲイン差が小さかったという記録だけでは、タイヤ条件全体への一般化は確認できない。軽量FastLap評価経路は6DOF/TMeasy近似でトルク操舵を拒否するため、現在はフルプラントと同じ用途を持つ予測器として使えない。

## 改善の段階

### 段階0 — 比較可能な基準実験を固定

以下をrun manifestとして保存する。

- Git commit、ビルド種別、コンパイラ、CPU
- トラックファイルと変換後プロファイルのhash
- 車両パラメータ、タイヤモデル、タイヤ重み／checkpointと正規化統計
- ドライバ設定、初期状態、乱数seed、終了条件
- 固定／再生成の速度プロファイルであるか
- 走行時間の計測定義（始終点、定常化区間、車輪がコースを越えた判定）
- シミュレーションwall timeと制御1回あたりwall timeを別の列として記録

基準ドライバは最低でもPID、LPV-LQR、Attack、MPCを同一条件で回す。毎回同一の速度プロファイルを使う比較と、各車両設定に合わせてプロファイルを再生成する比較は別実験とする。

**完了条件:** 別環境または別日でも条件差を特定でき、各runの処理時間・完走・軌跡が同じmanifestへ結び付く。

### 段階1 — 物理と周回進捗を先に正す

ドライバ高速化の前に、総合レビューに列挙した車体系の力腕・SATの符号疑義とトラック継ぎ目の投影を、小さな決定論的ケースで解決する。ここに間違いがあれば、より速い最適化で誤った物理への過適合を進める。

検証ケースには左右反転、正負操舵、正負縦力、一定半径旋回、閉路1周以上を含める。SATについてはTMeasy、Magic Formula、PINNそれぞれのMz符号変換と操舵応答を区別する。

**完了条件:** 期待する符号が文書とテストで一致し、閉路の終端前後で投影s・姿勢・参照点が連続する。

### 段階2 — 判断を変えない計算の再利用

予測候補の数や評価順を変える前に、重複計算を減らす。

1. トラックの弧長s、位置、方位、曲率、幅、基準速度を配列化し、周期を考慮した補間を用意する。
2. rolloutが使う前方速度上限を、トラックの速度包絡から前処理または一度のスキャンで得る。制動可能性を満たす包絡計算が速度制約を壊していないか検証する。
3. 同じ予測状態で繰り返す最近傍投影・参照検索を整理し、各候補・各ステップ当たりの呼び出し回数を明示する。
4. ステアリング・加減速候補が飽和で同じ値になる場合は重複候補を一度だけ評価する。
5. SIMD、並列化、キャッシュはprofileでボトルネックと同期費用を確認してから採用する。

ここでは候補、数値積分、コスト関数を変えず、既存と同じ入力に対する選択操作と出力が一致することを確認する。

**完了条件:** 同一ハードウェア・同一manifestで各候補・各rolloutの総時間、最近傍検索数、速度参照数を比較し、軌跡・操作・採用候補を許容誤差内で保つ。

### 段階3 — MPC/Attackの候補数とホライズンを測定可能に削減

計算コストの内訳を取った後、次の順に変更を評価する。

- 前周期に採用した操作列またはプリミティブをwarm startし、近傍候補を細かく、遠い候補を粗くする。
- 粗い安価モデルで全候補をふるい、上位K件だけを高精度rolloutする。
- プレビュー距離やホライズンを車速・曲率・制動距離に応じて短く／長くする。
- 操作プリミティブを無作為に増やすのではなく、操舵・速度の実行可能範囲をカバーするよう決める。
- 設計探索ではLPV-LQRまたは校正済み高速予測器で広く走査し、上位候補をフル14DOF/PINNで再評価する。

候補を減らしたことで急操舵、制動開始、障害・コース境界近傍の行動を取り逃がしていないか、固定プロファイルの評価で比較する。ハイパーパラメータをテスト走行へ何度も合わせない。

**完了条件:** 完走・境界余裕・入力制約・ラップタイムと計算時間のParetoを提示し、速度だけを根拠に既定ドライバを切り替えない。

### 段階4 — LPV-LQRの物理線形化と範囲を改善

LPV-LQRは現行の低コスト基準として保持する。Cf/CrがPINNプラントの局所応答を表すか、条件別に検査する。可能なら有効スリップ角範囲・荷重・車速でdFy/dalphaを同じタイヤモデルから取得し、steering actuator、遅れ、飽和、Mzの結合を含む線形化範囲を定める。PINN線形化へ切り替える場合は入力域外の外挿を避けるfallbackと安定性を確認する。

速度プロファイルに追従するLPV制御と、軌跡・速度を同時に選ぶ最適化は別機能である。再計画しないフローズンプロファイルで頑健性を調べた結果と、車両条件ごとに時間最適プロファイルを生成した結果を混ぜない。

**完了条件:** 同一の速度・曲率・荷重範囲で線形モデルと真値プラントの応答差を表にし、その有効範囲と逸脱時の挙動を明記する。

### 段階5 — 必要性が明確な場合だけオンラインNMPC/RTIを試す

現在の需要がオフラインの設計比較なら、追加のオンラインソルバより、固定プロファイル＋軽いフィードバックと高精度最終評価が最小の手段である。実車の制御周期内で全制約を再最適化する必要が出た場合は、対象ECU・期限・制約・予測モデルを先に定義したうえでRTI系SQPまたは構造化NMPCを比較する。

RTIは構造化NMPCで一回のNewton型反復を行う考え方の研究であり、本コードで実時間保証や性能向上を自動的に与えるものではない。導入時はウォームスタートの破綻、可行性回復、制約違反とWCETを実測する。

**完了条件:** 対象ハードウェア上でp99/maxの期限、制約充足、可行性回復、閉ループ安定性を示せる。ハードウェア要件が定まっていなければオンラインリアルタイム性の主張を保留する。

## 共通の評価ゲート

各変更は同一の固定track・タイヤ・車両・profileで比較する。評価値には次を含める。

| 評価軸 | 記録する値 |
|---|---|
| 完遂 | 完走、停止、数値異常、コース外逸脱の数 |
| 周回品質 | ラップ時間、進捗単調性、周回継ぎ目の誤投影数 |
| 経路追従 | 横偏差、方位偏差、曲率・速度別の誤差 |
| 操作 | 操舵角／トルク、変化率、加減速、飽和・レート制限の時間割合 |
| 車両余裕 | タイヤ荷重・合成力、車体境界余裕、サスペンション範囲 |
| 計算量 | 総wall time、sim秒あたりwall time、updateごとのp50/p95/p99/max |
| 一般化 | holdout車両・質量慣性・タイヤ条件・トラックでの完走と性能差 |

安全条件は「横偏差平均が小さい」だけで代用しない。パラメータ摂動と未使用の条件は、学習・調整に使ったケースから分ける。物理モデルの妥当性、数値計算の再現性、独立holdoutでの一般化、実車適合性は別々に報告する。

## 調査した関連研究とこの計画での使い方

- [Model predictive control for autonomous vehicle racing using a time-optimal approach](https://doi.org/10.1016/j.conengprac.2019.104270) は、オフラインの時間最適軌跡計画とLPV-MPCを組み合わせ、オンライン計算量を抑える方向の先例である。異なる車両・ソルバ・制約へそのまま性能を移せる証拠ではない。
- [Spline-Based Minimum-Curvature Trajectory Optimization for Autonomous Racing](https://arxiv.org/abs/2309.09186) は、スプライン制御点を使う最小曲率軌跡最適化の計算量削減を扱う。これは主にオフライン幾何軌跡計画の参考で、既存Attack/MPCのdrop-in代替や実車でのラップタイム保証ではない。
- [A Real-Time Iteration Scheme for Nonlinear Optimization in Optimal Feedback Control](https://cdn.syscop.de/publications/Diehl2005c.pdf) は、構造化NMPCでオンラインの反復計算を抑えるRTI法の基礎論文である。採用可否はこのリポジトリのモデル・制約・対象ハードウェアで別途測る。
- [Minimum curvature trajectory planning and control for an autonomous race car](https://portal.fis.tum.de/en/publications/minimum-curvature-trajectory-planning-and-control-for-an-autonomo/) は、オフライン軌跡生成と追従制御を分ける計画設計の関連例として参照する。

文献が示すのは方法とその研究条件である。本リポジトリでの精度、計算時間、物理妥当性を立証するものではない。

## 最初の実装候補

1. PHY-01〜03、DRV-01の解析ケース・テスト仕様を定める。
2. 共通run manifestとdriver profiling項目を追加して、現行LPV-LQR、Attack、MPCを同一条件で計測する。
3. プロファイル周期補間と投影再利用のように出力判断を維持しやすい最適化から適用する。
4. 結果をレビューしてから候補削減や高精度／低精度の段階評価へ進む。

この順なら、問題のある物理へ高速化を重ねずに、ドライバの意思決定を保った計算節約から始められる。
