# `apply_named_tire_model_selection.m`

## 概要
- あらかじめ定義されたタイヤモデル名を指定し、車両パラメータへ対応モデルを反映する関数群です。
- TMeasy、Magic Formula、PINN 系の候補を共通インターフェースで扱います。
- モデル選択だけでなく、利用可能な PINN カタログの走査や、プランナ用摩擦係数の推定も担当します。

## 主要関数・クラス
- `apply_named_tire_model_selection()` — 指定名に対応するタイヤモデル設定を車両仕様へ適用します。
- `scan_deployable_pinn_catalog()` — 配備可能な PINN モデル一覧を探索し、利用候補を集めます。
- `estimate_planner_mu()` — 選択したタイヤ特性から、プランナや評価関数用の代表摩擦係数を推定します。

## 理論・背景
- タイヤモデルは車両応答に強い影響を与えるため、モデル種類の差異を設計空間の一部として扱う価値があります。
- 一方で、各モデルは必要パラメータやデータ源が異なるため、呼び出し側で個別対応すると複雑化します。
- 本ファイルはモデル選択の窓口を統一し、評価系が「どのモデルか」を意識せずに走れるようにします。

## 外部ライブラリ・ツールボックス
- JSON 処理を使います。
- これは PINN カタログやモデル定義ファイルを外部記述し、MATLAB 側で柔軟に読み込むためです。
- 専用最適化ツールボックスは不要で、主にデータ選択と構造体更新を行います。

## 入出力
- 入力: ベース車両パラメータ、モデル名、場合によってはカタログや追加オプション。
- 出力: 選択済みタイヤモデルを含む更新済み車両パラメータ、補助的な推定値や検証結果。
- PINN カタログ走査では、配備可能モデルの一覧情報も返し得ます。

## システム上の役割
- タイヤモデル切替を共通化する選択レイヤです。
- 最適化、検証、可視化が同じ命名規約でタイヤモデルを指定できるようにします。
- 物理モデル系と学習モデル系を同じワークフローへ統合する上で重要です。
