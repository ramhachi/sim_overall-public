# `optimize_concept_design.m`

## 概要
- 車両コンセプトを上位レベルから最適化するスクリプト／関数群です。
- 質量、前後重量配分、空力、エンジンなどの主要因を中心に探索し、Skidpad や Circle 条件での性能を比較します。
- 階層的設計最適化の Phase 1 を担います。

## 主要関数・クラス
- `concept_cost_function()` — GA から呼ばれる概念設計の目的関数です。
- `create_concept_base_params()` — 概念探索用のベース車両仕様を構築します。
- `apply_vehicle_tradeoffs()` — 設計変数を物理パラメータへ反映します。
- 主処理は、これらを組み合わせて概念案の評価と最適解探索を進めます。

## 理論・背景
- いきなり全車両パラメータを最適化すると探索空間が大きすぎるため、まず主要概念だけを整える階層設計が有効です。
- 概念段階で大きな方向性を決め、その後の詳細最適化で微調整することで、探索効率と解釈性を両立できます。
- 本ファイルはその上流段階に相当し、空力・重量・パワーの大枠を決めます。

## 外部ライブラリ・ツールボックス
- GA を使うため Optimization Toolbox 系機能に依存します。
- Docker を使う理由は、各候補設計を C++ シミュレータで評価するためです。
- MATLAB 側は探索戦略と変数管理、C++ 側は物理評価という分担になります。

## 入出力
- 入力: 5 つ前後の概念変数、必要に応じて拡張チューナブル項目や評価条件。
- 出力: 最適化されたコンセプト案、Skidpad・Circle の結果、関連メタデータ。
- 中間的には GA 集団評価のため多数のシミュレーション結果が扱われます。

## システム上の役割
- 階層最適化の第 1 段階として、設計空間を大きく絞り込む役目です。
- Phase 2 のフル車両最適化へ良い初期点や設計方向を渡します。
- 初期構想の妥当性を定量比較するうえで、全体設計戦略の起点となります。
