# `VehicleSimRunner.m`

## 概要
- Docker 内で動く C++ 車両シミュレータを MATLAB から扱うためのクラスです。
- 車両パラメータ構造体を受け取り、トラック条件やドライバ条件を付与して実行し、結果を MATLAB 構造体として返します。
- 最適化ループと高忠実度物理シミュレーションを接続する中核インターフェースです。

## 主要関数・クラス
- `VehicleSimRunner` コンストラクタ — 実行環境、既定値、コンテナ状態などを初期化します。
- `run()` — シミュレーション実行の本体で、入力パラメータを JSON 等へ変換し、C++ 実行結果を読み戻します。
- `buildDriverArgs()` — PID ドライバや RL ドライバ向けの引数列を組み立てます。
- `ensureContainerRunning()` — Docker コンテナの起動・再利用・存在確認を担当します。

## 理論・背景
- 最適化では短時間に多数の候補を評価する必要がありますが、車両ダイナミクス本体は C++ 実装の方が高速です。
- 一方で探索戦略、設計変数管理、可視化は MATLAB との親和性が高いため、両者の境界を明確にする必要があります。
- 本クラスはその境界層として、MATLAB 側の柔軟性と C++ 側の計算性能を両立させます。

## 外部ライブラリ・ツールボックス
- Docker を使う理由は、C++ バイナリと依存関係を固定化し、MATLAB から再現性ある実行を行うためです。
- JSON を使う理由は、ネストした車両パラメータや実行条件を言語間で受け渡ししやすいためです。
- MATLAB 固有の高度なツールボックスがなくても、外部プロセス呼び出しとデータ整形で成立します。

## 入出力
- 入力: 車両パラメータ構造体、トラック名、半径、シミュレーション時間、ドライバ条件など。
- 出力: `lap_time`、`lateral_error`、速度履歴、成功可否などを含む結果構造体。
- 補助入力として、PID ゲインや RL モード指定などのドライバ設定も扱います。

## システム上の役割
- MATLAB 最適化群から C++ 物理エンジンを呼び出す共通窓口です。
- すべての評価関数が個別に Docker 制御を書く必要をなくし、実行手順を標準化します。
- 設計探索、検証、可視化の全段で再利用されるため、シミュレーション基盤の安定性を担保する重要コンポーネントです。
