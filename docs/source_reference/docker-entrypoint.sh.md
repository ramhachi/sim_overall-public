# `docker-entrypoint.sh`

> **要約**: Docker コンテナのエントリポイント。ビルド・テスト・開発モードの分岐を提供する。

## ファイルの目的

`Dockerfile` の `ENTRYPOINT` として指定され、コンテナ起動時の動作を引数で切り替える。CMake ビルド、CTest 実行、開発用シェルアクセスの 3 モードを提供する。

## 理論的背景

コンテナ運用では、ホスト環境と異なり毎回の起動条件を明示する必要がある。エントリポイントスクリプトで動作モードを切り替えることで、同一コンテナイメージをビルド・テスト・開発のすべてに使用できる。

## モード

| 引数 | 動作 |
|:---|:---|
| `build` | CMake 構成（Ninja）→ 並列ビルド |
| `test` | CTest 実行（`--output-on-failure`） |
| `dev` | Bash シェルを起動（対話モード） |
| その他 | 引数をそのまま `exec` で実行 |

## ビルド設定

- **ワークスペース**: `/workspace`
- **ビルドディレクトリ**: `/workspace/build`
- **CMake ジェネレータ**: Ninja
- **ビルドタイプ**: Release
- **並列ビルド**: `--parallel`（CPU コア数自動検出）

## 入出力

- **入力**: コンテナ起動時の引数（`build`, `test`, `dev`, またはカスタムコマンド）
- **出力**: ビルド成果物 or テスト結果 or 対話シェル

## システム上の役割

`docker-compose.yml` や `docker compose run` から呼ばれるコンテナのエントリポイント。`build_easystart_docker_environment.m` は直接 `bash -c` で別のビルドスクリプトを呼ぶため、このエントリポイントは主にマニュアル操作や CI で使用される。
