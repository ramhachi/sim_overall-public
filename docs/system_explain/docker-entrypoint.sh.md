# `docker-entrypoint.sh`

## 役割

- `fsae-sim` コンテナ内で、起動引数に応じて**ビルド・テスト・開発シェル**へ分岐するエントリポイントスクリプトです。
- Docker 実行時の初期コマンドを薄く整理し、定型作業をコンテナ外から呼びやすくしています。

## 運用上の入口

- コンテナ起動時に実行されます。
- 主な引数は `build`, `test`, `dev` の 3 系統です。

## 分岐内容

### `build`
- `/workspace/build` を作成して移動
- `cmake .. -G Ninja -DCMAKE_BUILD_TYPE=Release`
- `cmake --build . --parallel`
- 役割: コンテナ内の Release ビルドを一発で通す

### `test`
- `/workspace/build` へ移動
- `ctest --output-on-failure`
- 役割: 既存ビルドディレクトリを前提にテストだけ回す

### `dev`
- `exec /bin/bash` で対話シェルへ入る
- 役割: 手動調査・追加コマンド実行

### その他
- `exec "$@"` で任意コマンドをそのまま実行します。

## 入出力・副作用

- **入力**: コンテナ起動引数
- **出力**: 標準出力ログ、ビルド成果物、テスト結果
- **副作用**:
  - `/workspace/build` を作成・更新
  - 引数に応じてビルドやテストを実行
- `set -e` により途中失敗で即終了します。

## データフロー

1. 第 1 引数を評価
2. 既定サブコマンドに一致すれば定型処理を実行
3. 一致しなければ受け取ったコマンドへ制御を移譲

## システム内での位置づけ

- Docker ベース運用での**最初のコマンドディスパッチャ**です。
- `build_easystart_docker_environment.m` や `docker compose run` から渡されるコマンドを受け、コンテナ内作業を標準化します。
